Sesi ini tidak tentang membangun blog yang rumit. Tujuannya satu: setiap orang di ruangan ini bisa pulang dengan situs sendiri di yourname.github.io, tanpa server dan tanpa biaya hosting.

Yang kita pakai hanya tiga hal: repo publik, folder lokal, dan aplikasi opencode. Semua yang lain di workspace saya sifatnya opsional untuk sesi ini.

Mulai dengan janji yang kecil. Jangan buka daftar fitur di menit pertama.

(01)the promise[ build your own blog ]

one afternoon. one site that is yours.

you do not need a server, a database, or a build pipeline. you need a repo, a folder, and something that can type.

01 / host

free hosting

a public repo named yourname.github.io. github pages serves it at that address, with no extra service to pay for.

02 / files

plain pages

html and css you can read. no hidden build step between the file you write and the page a reader opens.

03 / name

your name on it

your commits, your words, your taste. a custom domain later is one small file and a dns record.

the only bill is the model you connect.

github pages gratis untuk repo publik. Kalau reponya privat, pages butuh paket berbayar, jadi untuk latihan ini reponya dibuat publik sejak awal.

Situsnya hanya html dan css. Tidak ada database, tidak ada server yang harus dijaga menyala, dan tidak ada tagihan bulanan untuk halaman yang jarang dibuka.

Tekankan bahwa ini situs milik mereka, bukan akun di platform orang lain.

(02)the stack[ build your own blog ]

three pieces, in this order.

each one has one job. when something breaks, you know which piece to open.

01 the repo

a public folder on github. this is the published site, and the history of every change you make to it.

02 the local folder

where the files live on your machine, and where the agent reads and writes. versioned with git, so nothing is lost.

03 opencode desktop

the app that opens the folder, reads your rules, and runs the agents you define there.

repo → folder → app → page

everything else i run, a chat bot, a relay, a server, a domain, is optional. this session stops at the published page.

Urutannya sengaja sederhana. Repo adalah tempat hasil akhir. Folder adalah tempat kerja. Aplikasi adalah yang membaca folder itu.

Kalau salah satu bermasalah, kita bisa menunjuk bagian yang salah tanpa menebak. Repo bermasalah berarti git. Folder bermasalah berarti file atau config. Aplikasi bermasalah berarti instalasi atau model.

Sebutkan sekali bahwa relay dan bot di workspace saya tidak dibutuhkan hari ini, lalu lanjut.

(03)step 01 / install[ build your own blog ]

start with the desktop app.

the app is in beta and updates itself. it holds the editor, the file tree, and the agent in one window, so there is no terminal to learn first.

installpick one line
windowswinget install --id Anomaly.OpenCode.Desktop -e
macosbrew install --cask opencode-desktop
no packageopencode.ai/download

then connect one model

  • open settings, sign in, or paste a provider api key
  • pick one small model to start, you can raise it later
  • the key bills per token, and it never goes into the repo

if you live in a terminal

  • the cli runs the same engine with the same config
  • windows package managers are not supported for the cli
  • today we stay in the app, because it is one install

Install lewat winget di windows, brew di macos, atau unduh langsung dari opencode.ai/download. Aplikasi ini masih beta, tapi sudah cukup stabil untuk dipakai harian dan update sendiri.

Setelah terbuka, sambungkan satu model. api key ditagih per token, jadi mulai dari model kecil dan naikkan hanya kalau tugasnya butuh. Simpan key di pengaturan aplikasi, jangan pernah di dalam folder repo.

Kalau ada yang bertanya soal cli, jawab singkat: mesinnya sama, tapi sesi ini memakai aplikasi supaya satu instalasi selesai.

(05)step 03 / roster[ build your own blog ]

one orchestrator, four helpers.

you talk to one agent. it delegates, checks, and reports back. the helpers stay out of your way.

  • builderwrites and edits the page, the styles, and the small scripts.
  • scribedrafts the copy, keeps the structure, and matches the house voice.
  • skepticargues with the draft: weak claims, missing cases, false confidence.
  • verifierruns the gates and reports what actually passed.
delegation hidden from you one writer per file

Kamu hanya berbicara dengan orchestrator. Dia yang memecah tugas, memilih agent, dan merangkum hasilnya kembali ke kamu.

Builder menulis, scribe merapikan copy, skeptic mencari lubang, verifier menjalankan cek. Subagent tidak bisa menghubungi kamu langsung, tidak bisa mendelegasikan lagi, dan tidak bisa menyetujui pekerjaannya sendiri.

Bilang bahwa mulai dari dua peran juga tidak apa-apa. Roster ini tumbuh sesuai kebutuhan, bukan sejak hari pertama.

(06)the honest half[ build your own blog ]

they draft fast. they do not know when they are wrong.

the split is simple: let the agents do the boring half, and keep the judgment for yourself.

the agents do this

  • turn one brief into three draft shapes you can choose from
  • keep the page structure and the tokens consistent
  • run the gates and tell you which one failed
  • summarise what changed, so review takes minutes

you still own this

  • the thesis, and the one thing the post is actually about
  • which claims are true, and which ones you can defend
  • the taste call: shorter, warmer, less clever
  • the publish button, and the answer for what you shipped

this deck and the murphy deck were built this way. a human kept the claims, the taste, and the publish button.

Model cepat menulis, tapi tidak tahu kapan dirinya salah. Jadi pekerjaan yang bisa dicek mesin kita serahkan ke mesin, dan yang butuh penilaian tetap di manusia.

Contohnya: memilih tesis, memastikan klaim bisa dipertanggungjawabkan, dan memutuskan kapan tulisan sudah cukup. Tiga hal itu tidak bisa didelegasikan tanpa kehilangan sesuatu.

Dua deck di blog ini dibuat dengan pola yang sama. Sebut ini sebagai bukti, bukan sebagai janji.

Brief yang jelas menghemat satu jam bolak-balik. Empat baris sudah cukup: goal, context, done when, constraints.

Bagian done when yang paling sering dilupakan. Kalau tidak ada kriteria selesai, agent akan terus menambah bagian sampai terasa lengkap, dan lengkap belum tentu benar.

Minta semua orang menulis satu brief di catatan sebelum sesi selesai.

(08)the gates[ build your own blog ]

five cheap checks, every time.

a script does not get tired, does not skip the boring page, and does not want to go home early.

  • 01viewport at 320no sideways scroll on a small phone, the layout holds its shape.
  • 02anchors resolveevery in-page link lands on a real id, not a 404 with extra steps.
  • 03alt text existsan image says what it is, for the reader who cannot see it.
  • 04sitemap is currentevery page listed, dated with the commit that changed it.
  • 05no secretsno keys, tokens, or phone numbers anywhere in the repo.

run the script, do not trust the summary. a gate you skip is a gate you do not have.

Lima cek ini murah dan menangkap sebagian besar kesalahan yang sering lolos. Ukuran layar, anchor, alt text, sitemap, dan rahasia yang tidak sengaja masuk repo.

Jalankan script-nya, jangan hanya membaca ringkasan dari agent. Gate yang dilewati sama saja dengan gate yang tidak ada.

Kalau waktu sempit, cek nomor lima dulu. Kebocoran key jauh lebih mahal daripada link yang mati.

Lima perintah, lalu tiga klik di settings. Setelah sekali berhasil, publish berikutnya cukup git add, commit, push.

Repo harus publik untuk plan gratis. Kalau ada draft yang belum siap dilihat orang, jangan dimasukkan ke repo ini. Tidak ada folder rahasia di repo publik.

Minta semua orang menyelesaikan ini sebelum sesi selesai, supaya masalahnya ketahuan sekarang, bukan minggu depan.
