Reverse-Engineering Client Binaries: Extracting Ground-Truth Design Systems for High-Velocity Prototyping

By Ramadhana Bhanuharya Krishnamurti (Krishna / naquuuu) • Technical Product Owner

the core thesis in 30 seconds

In enterprise retail and fintech apps, design files in Figma almost never match what is compiled in production. Disorganized multi-brand design debt, deprecated color variables, and missing edge-state screens cause massive sprint delays. In this post, I detail how we bypass Figma bottlenecks entirely: decompiling compiled client binaries (APKs), programmatically harvesting raw vector drawables and variable fonts into a unified CSS/JS design engine, and serving pixel-perfect interactive mobile prototypes through zero-friction Vercel Edge gates.

1. The Multi-Surface Drift Crisis in Enterprise Mobile Apps

Every technical product manager in a large-scale consumer enterprise encounters the same painful paradox:

  • The Figma Canvas is an Illusion: Product designers create idealized, happy-path wireframes in Figma. But as features ship week after week, the production app diverges. New gradient stops are hardcoded, custom Android drawables are patched into native builds, and the design file becomes an out-of-date artifact.
  • Sprint Estimation Paralysis: When engineering teams are asked to build a new feature (e.g., Apple VIP Reservation or Tiered Points Invoicing), frontend developers spend 40% of their sprint wrestling with inconsistent paddings, mismatched hex tokens, and missing typography definitions.
  • Stakeholder Review Latency: Executive leadership and brand directors cannot evaluate static screenshots. They demand to touch and tap real interactive prototypes on physical mobile hardware before signing off on business requirements.

If your prototyping workflow relies on waiting for designers to tidy up a 200-page Figma file, you have already lost the velocity war. The fastest, most accurate source of truth is not the design tool: it is the compiled binary currently running in production.

3. Technical Execution: Decompiling APKs into Clean Web Components

Building the extractor script (scripts/extract_apk_design_system.py) required solving three concrete engineering hurdles:

A. Converting Android VectorDrawables into Standard SVG

Android native binaries encode vectors using an XML format with attributes like android:pathData and android:fillColor. Standard web browsers cannot render VectorDrawables natively. Our python extractor parses the XML tree, maps android:viewportWidth to standard SVG viewBox, and translates color resource references into inline SVG paths.

B. Variable Typography and Tier Badge Assets

Rather than guessing web font fallbacks, we pull the exact font files shipped in the APK's assets/fonts/ directory. Brand-critical assets (such as the MAPCLUB Gold/Platinum loyalty tier badges, partner logos, and barcode glyphs) are extracted as clean, lossless vectors and placed directly into our workspace design library.

C. The Hardware-Accurate Mobile Shell

When an executive opens a prototype URL on desktop, standard web layouts feel unnatural because mobile user experience is constrained by physical touch ergonomics. We created mapclub-mobile-shell.js:

  • On desktop screens (width > 640px), the prototype automatically mounts inside an authentic iPhone 16 Pro / Pixel 8 hardware frame with dynamic Island/notch rendering and realistic drop shadows.
  • On physical mobile devices, the outer shell automatically collapses, allowing the prototype to take over 100% of the viewport with zero scrollbar glitching.

4. Zero-Trust Security: Protecting Prototypes without Auth Friction

Enterprise prototypes often contain sensitive forward-looking features (e.g., unpublished corporate partnerships or unannounced tier revamps). How do you protect prototypes from public crawlers without forcing busy C-level stakeholders to install corporate VPNs or remember complex enterprise SSO passwords?

We solved this at the network edge with Vercel Edge Middleware:

  1. Server-Side Edge Interception: Every request to /prototypes/* is inspected by an edge function in under 5ms before static assets are served.
  2. Passcode Cookie Verification: The edge function checks for a secure authentication cookie. If absent, the user is redirected to a sleek passcode verification wall.
  3. Zero-Friction Magic Links: For WhatsApp and Slack sharing with internal directors, we generate an instant access link:
    https://mapclubkris.vercel.app/prototypes/apple-vip-npi/?access=mapclub2026
    The edge function intercepts the query parameter, sets an encrypted cookie, clears the URL parameter for privacy, and immediately renders the prototype.

5. Business Impact & Lessons Learned

Shifting our product team from static wireframes to reverse-engineered, edge-gated prototypes fundamentally transformed our operating velocity:

4x Reduction in Alignment Latency
Stakeholders approve features in a single 15-minute review by interacting with real simulated clicks, instead of debating abstract 30-page requirements documents.
Zero Estimation Re-work
Because the prototype is built with the exact tokens and component hierarchy of the production client, frontend engineers can copy DOM structures directly into their sprint branches.

6. Summary: The PM as a Systems Compiler

Modern digital leadership is no longer about writing descriptive prose and passing tickets over a wall. As product managers, our responsibility is to build closed-loop systems where commercial goals, ground-truth code, and user empathy converge. When you ground your prototypes in the physical reality of compiled code, your velocity is unbeatable.
